# MongoDB Setup — In Detail
**Road Damage Detection System · Group 3 · UFV**

This document describes how MongoDB Atlas is provisioned for RDDS, why the
collections and indexes are shaped the way they are, and how to run the Step 1
setup + smoke test on a new machine. It is designed so that any team member can
reproduce the database setup from scratch and verify it works before moving to
Step 2.

---

## 1. Why MongoDB (and not Postgres)

RDDS stores three very different kinds of records: image metadata (annotations
are nested lists of variable length), experiment records (hyperparameter dicts,
per-epoch metrics, checkpoint URLs) and prediction outputs (another nested list
of detections). A relational schema would require three or four auxiliary tables
per logical entity (annotations, hyperparams, metrics, detections) and constant
migrations as we add new fields during the project.

MongoDB's document model absorbs this variation naturally. We pay for it in two
ways — no foreign-key integrity and no SQL — but neither matters here: we never
join across collections at query time, and we query by a handful of
well-understood keys (`image_id`, `run_id`, `is_production`).

**Design principle:** *images live on the filesystem; MongoDB stores everything
else.* Training reads images directly from local disk, which keeps I/O fast and
avoids BSON's 16 MB document size limit.

## 2. Atlas Cluster Provisioning

### Owner
L creates the cluster once. The URI is shared with M and J through a secure
channel (never in Git, never in chat history that is not private).

### Steps
1. Sign in at https://cloud.mongodb.com. Create an organisation `RDDS-UFV` and
   a project `rdds`.
2. Deploy a new cluster: **M0 Free tier**, AWS, region closest to Madrid
   (eu-west-1 Ireland is fine). Cluster name: `rdds`.
3. **Database Access** → Add a new database user with password authentication.
   Username `<db-user>`, auto-generate password. Role: `readWrite` on database
   `rdds`. Record the password — it is shown only once.
4. **Network Access** → Add IP address `0.0.0.0/0` (allow from anywhere). This
   is acceptable for an academic project because the cluster is protected by
   the password generated in step 3 and contains no personal data. Restrict
   the CIDR block later if the cluster ever holds anything sensitive.
5. **Connect** → Drivers → Python → copy the `mongodb+srv://...` URI. Replace
   `<password>` with the real password and `<dbname>` with `rdds`. This is the
   `MONGO_URI` value that goes in each teammate's `.env`.

### URI format
```
mongodb+srv://<db-user>:<password>@rdds.<cluster-hash>.mongodb.net/rdds?retryWrites=true&w=majority
```

The hostname (`rdds.<cluster-hash>.mongodb.net`) is auto-generated by Atlas and
will be different on each new cluster. Do not commit the URI. The
`.env.example` in the repo shows a placeholder for this reason.

## 3. Database and Collections

One database — `rdds` — with three collections:

| Collection        | One document per | Primary key |
|-------------------|------------------|-------------|
| `images_metadata` | image            | `image_id`  |
| `experiments`     | training run     | `run_id`    |
| `predictions`     | inference result | `pred_id`   |

`_id` (Mongo's native ObjectId) is also present on every document but we never
query by it. Queries go through the domain keys above, which is why we index
them explicitly.

### 3.1 `images_metadata`
```json
{
  "image_id": "a3f8c2d1...",
  "filepath": "Japan/train/00001.jpg",
  "country": "Japan",
  "source_device": "smartphone",
  "split": "train",
  "width": 600,
  "height": 600,
  "annotations": [
    { "label": "D00", "xmin": 120, "ymin": 80, "xmax": 340, "ymax": 200 }
  ]
}
```

**`image_id` = MD5(filepath).** Not an ObjectId. The reason is reproducibility:
any team member who downloads RDD2022 and runs the ingestion pipeline
independently must produce the *same* IDs for the same images. If we used
ObjectId (which is time- and host-dependent), experiment records that reference
`training_image_ids` would only make sense on the machine that ingested the
data. MD5 of the relative filepath is deterministic, collision-free at this
dataset size (~47k images), and cheap to compute.

**`filepath` is relative to `RDD_DATA_ROOT`**, a per-machine env var in `.env`.
The absolute path is resolved at runtime:
```python
full_path = os.path.join(os.getenv("RDD_DATA_ROOT"), image["filepath"])
```
This lets the same `images_metadata` document work on the laptop, the 4060 and
the A100 without modification — each machine has its own `RDD_DATA_ROOT`.

### 3.2 `experiments`
One document per training run. Stores the hyperparameter config, training-set
image IDs, final metrics, checkpoint URLs (Backblaze B2) and the lifecycle
flags.

Key fields:
- `status` — one of `running | completed | promoted | superseded`.
- `is_production` — **exactly one document has this `true` at any time.** Set
  and unset atomically during promotion (see §6).
- `training_image_ids` — lets any run be recreated from its document alone.
- `metrics.F1_overall` — primary reported metric (CRDDC2022 protocol, see
  Pipeline §Stage 4). `metrics.mAP50` is kept as the training-time tracker and
  for continuity with Ultralytics logs.

### 3.3 `predictions`
One document per inference result. Unchanged from Pipeline §Stage 2.

## 4. Indexes

Indexes are the reason `setup_atlas.py` exists as a standalone script. Without
them, every query during training and inference is a full collection scan.
With them, the same queries are O(log N) point lookups. Index creation in
`pymongo` is idempotent: running the script twice is safe and does nothing on
the second run.

| Collection        | Index                      | Type      | Why |
|-------------------|----------------------------|-----------|-----|
| `images_metadata` | `image_id`                 | unique    | Upsert guard during ingestion; point lookup during training. |
| `images_metadata` | `country`                  | ascending | Filter by country for stratified splits and analysis. |
| `images_metadata` | `split`                    | ascending | Separate train/val/test sets at query time. |
| `images_metadata` | `split + country`          | compound  | `split=train, country=Japan` — the hot query during training. |
| `experiments`     | `run_id`                   | unique    | Point lookup when updating status or uploading checkpoints. |
| `experiments`     | `is_production`            | ascending | `find_one({is_production: true})` — called at every inference start. |
| `experiments`     | `status`                   | ascending | Dashboard-style queries (`running`, `completed`). |
| `experiments`     | `model`                    | ascending | Filter by architecture (`yolo11s` vs `yolo11m`). |
| `predictions`     | `pred_id`                  | unique    | Deduplication. |
| `predictions`     | `image_id`                 | ascending | "Show all predictions for this image across model versions". |
| `predictions`     | `model_version`            | ascending | "Show everything this model version predicted". |
| `predictions`     | `image_id + model_version` | compound  | The canonical inference-result lookup. |

## 5. Step 1 Code

Three scripts under `src/db/`, all driven by `MONGO_URI` from `.env`.

### 5.1 `src/db/connection.py`
Single function `get_db()` returns a handle to the `rdds` database. The client
is cached with `functools.lru_cache(maxsize=1)` so all callers share one
connection pool for the lifetime of the Python process.

```python
from src.db.connection import get_db
db = get_db()             # pymongo.database.Database
db.images_metadata        # pymongo.collection.Collection
```

If `MONGO_URI` is missing from `.env`, `get_db()` raises `EnvironmentError`
with an explicit message. This is a loud failure by design — a silent
connection to localhost would be worse.

### 5.2 `src/db/setup_atlas.py`
Idempotent script that creates the three collections and all indexes listed in
§4. Creating a collection that already exists is a no-op in Mongo; creating an
index that already exists is a no-op via `create_index()`. Run it once per
cluster.

```bash
python -m src.db.setup_atlas
```

### 5.3 `src/db/test_connection.py`
End-to-end smoke test. For each of the three collections it inserts a sentinel
document (key `__smoke__<random-hex>`), reads it back, and deletes it. Prints
`OK` on success. Run immediately after `setup_atlas.py`:

```bash
python -m src.db.test_connection
```

**Invocation matters:** both scripts must be run as *modules* (`python -m ...`)
from the repository root, not as files (`python src/db/test_connection.py`).
Running them as files breaks the `from src.db.connection import get_db`
import because `src` is not on `sys.path`.

## 6. Model Promotion Atomicity

The `is_production` flag is the single source of truth for which model the
inference module loads. The invariant — exactly one experiment document has
`is_production=true` at any instant — is enforced at write time, not schema
time, because Mongo does not support partial unique indexes the way Postgres
does.

Promotion algorithm (pseudocode):
```python
current = db.experiments.find_one({"is_production": True})
if new.metrics["F1_overall"] > current.metrics["F1_overall"] + 0.01:
    with client.start_session() as s:
        with s.start_transaction():
            db.experiments.update_one(
                {"_id": current["_id"]},
                {"$set": {"is_production": False, "status": "superseded"}},
                session=s,
            )
            db.experiments.update_one(
                {"_id": new["_id"]},
                {"$set": {"is_production": True, "status": "promoted"}},
                session=s,
            )
```

The transaction guarantees there is no instant in time where two documents
have `is_production=True` or where none do. Atlas free-tier clusters are
replica sets by default, which is the minimum required for multi-document
transactions in Mongo.

Promotion uses **F1 overall at IoU ≥ 0.5**, matching the official CRDDC2022
ranking metric. See Pipeline §Stage 4 for the evaluation protocol.

## 7. Troubleshooting

**`pymongo.errors.ConfigurationError: SRV resolution failed`** — the cluster
hostname cannot be resolved. Check internet connectivity and that the URI was
pasted correctly. DNS from university/VPN networks occasionally blocks SRV
records; switching to the non-SRV `mongodb://host1,host2,host3/rdds` form
(shown in Atlas under "Connection String > Standard") bypasses this.

**`OperationFailure: Authentication failed`** — password is wrong or the user
was not given `readWrite` on the `rdds` database. Re-check in Atlas →
Database Access.

**`ServerSelectionTimeoutError`** — your IP is not in the Atlas network access
list. Add it (or `0.0.0.0/0`) and retry.

**Smoke test fails with `ModuleNotFoundError: No module named 'src'`** — you
ran the script as a file (`python src/db/test_connection.py`) instead of a
module (`python -m src.db.test_connection`). See §5.3.

**`.env` changes do not take effect** — the Python process caches the client
via `@lru_cache`. Start a fresh shell / kill the REPL and rerun.

## 9. CLI reference

### `python -m src.db.setup_atlas` — Create collections and indexes

No configurable flags — run as-is. The script is idempotent: running it
twice on the same cluster leaves indexes unchanged.

**Windows (PowerShell)**
```powershell
.venv\Scripts\activate
python -m src.db.setup_atlas
```

**macOS / Linux**
```bash
source .venv/bin/activate
python -m src.db.setup_atlas
```

No configurable flags. `MONGO_URI` must be set in `.env`.
